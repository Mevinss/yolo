# Результаты шага 5: локальный уровень и слияние

Научное ядро реализовано. Система впервые работает целиком: маршрут
по OSM Астаны и обстановка с камеры сходятся в одну голосовую подсказку.

Воспроизведение:

```bash
python tools/demo_pipeline.py --steps 300 --lang ru
```

```bash
python -m pytest tests/ -q
```

## 1. Что реализовано

| Модуль | Что делает |
|---|---|
| `core/risk/field.py` | объекты → полярная сетка риска |
| `core/local_planner/corridor.py` | сетка → профиль R(θ) и свободные коридоры |
| `core/fusion/policy.py` | **argmin cost(θ)** — согласование маршрута и обстановки |

| `core/guidance/scheduler.py` | арбитраж речи с бюджетом и вытеснением |

## 2. Сквозной прогон

Маршрут Байтерек → Хан Шатыр, 2150 м, 32 манёвра, 94.6 % пути
по пешеходной инфраструктуре. 300 кадров, YOLOv8m на RTX 4050.

| Показатель | Значение |
|---|---|
| Медианная задержка кадра | **46 мс** |
| p95 | 53 мс |
| Частота обработки | **≈22 к/с** |

Разбивка по слоям (мс): восприятие 39.0, риск 0.1, локальный 0.2,
маршрут 0.2, слияние 0.1, речь 0.0.

**Всё, кроме восприятия, занимает менее миллисекунды.** Двухуровневая
навигация практически бесплатна поверх детекции — стоимость системы
определяется детектором, а не слиянием.

### Оговорка о честности

Положение в этом прогоне синтетическое: пользователь движется
по полилинии с постоянной скоростью, а кадры берутся из датасета
и не соответствуют этому положению. Это проверка связности системы,
а **не измерение качества навигации**. Настоящие цифры дадут записанные
прогулки на шаге 6, где кадр и координата принадлежат одному моменту.

## 3. Влияние CUDA

torch был собран без CUDA, и RTX 4050 простаивала.

| Конфигурация | Медиана | к/с |
|---|---|---|
| yolov8m, 640px, CPU | 473 мс | 2.1 |
| yolov8n, 320px, CPU | 63 мс | 16.0 |
| **yolov8m, 640px, RTX 4050** | **46 мс** | **≈22** |

На GPU более крупная и точная модель работает быстрее, чем самая
лёгкая на процессоре. Это меняет рабочую точку системы: выбирать
между точностью и скоростью больше не требуется.

Для сравнения: в работе Ж. Каржаубай заявлено 18–22 к/с на Intel
i5-11400 без GPU. Наши 16 к/с при yolov8n/320 на Ryzen 5 7535HS
сопоставимы, и заявленные цифры подтверждаются как достижимые.

## 4. Четыре дефекта, найденные прогоном

Все обнаружены только при работе системы целиком — модульные тесты
их не ловили, потому что каждый модуль по отдельности был корректен.

### 4.1 Ошибка нормировки профиля риска

Свёртка поля по дальности делилась на сумму весов полос. Яма в метре
занимает только ближнюю полосу и давала около 0.5 при пороге блокировки
0.7, то есть **не считалась препятствием вовсе**.

Исправлено делением на максимальный вес: занятая ближняя полоса даёт
1.0, дальняя — около 0.06. Опасность направления определяется
ближайшей преградой, а не средней по дальности.

Тест: `test_near_obstacle_blocks_but_far_does_not`.

### 4.2 Следующий манёвр выбирался по расстоянию по прямой

`Router.track` брал ближайший манёвр, и на старте им всегда оказывался
`DEPART`, на котором пользователь стоит. Система молчала обо всех
поворотах до тех пор, пока не отходила достаточно далеко.

Исправлено: следующий манёвр — первый **строго впереди по маршруту**,
точка отсчёта — положение вдоль полилинии.

### 4.3 Лестницы не объявлялись

`_maneuver_phrase` обрабатывал только повороты. Лестница для незрячего
опаснее поворота — пропущенная ступень вниз означает падение — но
о ней система молчала.

Добавлено объявление лестниц с указанием наличия перил.

### 4.4 Подтверждающие реплики повторялись каждые восемь секунд

«Свободно» и «через сорок метров направо» звучали заново по истечении
окна дедупликации. За две минуты это давало 14.4 реплики в минуту
при почти нулевой новой информации.

Исправлено двумя способами: подтверждающие реплики получили окно
в 40 секунд, а объявления манёвров привязаны к рубежам 40/15/5 метров
и произносятся по одному разу на рубеж. Итог — 7.2 реплики в минуту.

## 5. Ошибка проектирования, закрытая тестом

`test_fence_scenario` воспроизводит ситуацию, ради которой на шаге 2
переделывался контракт `LocalGuidance`:

```
маршрут прямо (0°), забор занимает −32°…+19°
свободны коридоры при −46° (широкий) и +25° (узкий)
```

При передаче одного угла слияние получило бы −46° как самый широкий
и искало компромисс между −46° и 0°, выбрав около −25° — **внутрь
забора**. С профилем R(θ) оно выбирает +25°: уже, но свободно
и ближе к маршруту.

## 6. Ограничения

* Веса `w_risk`, `w_route`, `w_smooth` не откалиброваны на людях.
  Кривая компромисса строится на шаге 6.
* Пороги переходов (25 м / 3 м) и рубежи предупреждения (40/15/5 м)
  взяты из здравого смысла, а не из измерений.
* MiDaS не подключена к конвейеру: опасности без класса реализованы
  в `depth.py`, но в прогоне не участвовали.
* Казахские формулировки требуют проверки носителем языка.
* Приложение не запускалось на реальном iPhone.
